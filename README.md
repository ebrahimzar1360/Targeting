# هدف‌نگار

**هدف‌گذاری به روش «ماتریس ساختار طراحی»: از چشم‌انداز تا اقدام**

هدف‌نگار یک وب‌اپ فارسی و راست‌چین است که روی موبایل و کامپیوتر کار می‌کند، نصب‌شدنی است (PWA) و آفلاین هم کار می‌کند.
در این روش، هدف‌ها از فاصله‌ی «وضعیت موجود» تا «وضعیت مطلوب» بیرون می‌آیند. هر هدف به فعالیت‌های تاریخ‌دار وصل می‌شود، و اپ خودش بودجه، ظرفیت زمانی و ناهماهنگی‌ها را حساب می‌کند.

- بدون سرور و بدون ثبت‌نام؛ داده‌ها فقط در مرورگر همان دستگاه ذخیره می‌شوند.
- خروجی و ورودی JSON و Excel دارد و فایل‌های Excel قبلی با قالب «جدول الزامات» و «Action plan» هم خوانده می‌شوند.
- دستیار هوش مصنوعی (Claude) اختیاری است؛ برنامه بدون آن هم کامل کار می‌کند.

---

## روش در چهار گام

| گام | صفحه در اپ | چه می‌کنید |
|---|---|---|
| ۱ | چشم‌انداز و افق | چشم‌انداز در یک جمله، «الگو»، افق زمانی، ظرفیت ساعتی هفتگی، بازه‌ی بودجه، فازها و نقاط عطف |
| ۲ | ماتریس الزامات | در ۷ دسته (دانش، تجربه، مهارت، نیروی انسانی، تجهیزات و ساختمان، مجوزها، منابع مالی): وضعیت مطلوب، وضعیت موجود، **هدف قابل‌سنجش** با موعد و اولویت |
| ۳ | برنامه عملیاتی | هر هدف ← برنامه ← فعالیت‌ها، با تاریخ شروع و پایان، مسئول، منابع، **ساعت** و **هزینه** به‌صورت عدد |
| ۴ | شاخص‌ها، بودجه، بازبینی | ثبت عدد واقعی KPI در پایان هر ماه، هزینه‌ی واقعی، و بازبینی ۳۰ دقیقه‌ای هر هفته |

## امکانات

- **داشبورد:** پیشرفت کل در برابر پیشرفتی که طبق زمان‌بندی انتظار می‌رود، فعالیت‌های جاری و عقب‌افتاده، بار کاری هفته، بودجه، و پیشرفت هر ۷ دسته.
- **سلامت برنامه:** این بخش خودکار موارد زیر را پیدا می‌کند و هر مورد با یک کلیک قابل اصلاح است:
  - هدفی که فعالیت ندارد، یا فعالیتی که به هدفی وصل نیست؛
  - فعالیتی که دیرتر از موعد هدفش تمام می‌شود؛
  - هدفی که عدد یا موعد ندارد؛
  - بودجه‌ی بیش از سقف، و هفته‌های بیش از ظرفیت.
- **نمودار ظرفیت:** ساعت فعالیت‌ها روی هفته‌ها پخش می‌شود و با ظرفیت واقعی شما مقایسه می‌شود.
- **دو نمای برنامه‌ی عملیاتی:** فهرست، با گروه‌بندی بر اساس هدف یا فاز یا بدون گروه، و نمای زمان‌بندی (گانت).
- **ابزارهای ورود اطلاعات:** تقویم شمسی، اعداد فارسی، حالت تیره، و برگرداندن هر تغییر با «برگرداندن» یا <kbd>Ctrl+Z</kbd>.
- **چند برنامه:** می‌توانید چند برنامه‌ی جدا داشته باشید (مثلاً شخصی و کاری) و از هر کدام کپی بسازید.
- **نمونه‌ی آماده:** برنامه‌ی یک‌ساله‌ی «مشاور کسب‌وکار و سیستم‌سازی با AI» با ۳۶ الزام و ۶۰ فعالیت.

## دستیار هوش مصنوعی (اختیاری)

کلید API از [console.anthropic.com](https://console.anthropic.com) را در «تنظیمات» وارد کنید. کلید فقط روی همان دستگاه می‌ماند و درخواست‌ها مستقیم از مرورگر به Claude فرستاده می‌شوند.

- پیشنهاد الزام برای هر دسته
- پیشنهاد ۳ گزینه‌ی هدف قابل‌سنجش برای هر الزام
- پیشنهاد فعالیت‌های تاریخ‌دار با ساعت و هزینه
- نقد کل برنامه مثل یک مشاور

دستیار فقط پیشنهاد می‌دهد و چیزی را خودکار تغییر نمی‌دهد. مدل پیش‌فرض Claude Opus 5.5 است و Sonnet 5.5 هم قابل انتخاب است.

## اجرا و انتشار

### اجرا روی کامپیوتر خودتان

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # تست‌ها
npm run build    # خروجی نهایی در پوشه‌ی dist
```

### انتشار رایگان روی GitHub Pages

۱. این شاخه را در `main` ادغام کنید.
۲. در GitHub بروید به **Settings ← Pages** و در بخش **Source** گزینه‌ی **GitHub Actions** را انتخاب کنید.
۳. با هر push روی `main`، تست‌ها اجرا می‌شوند و اپ روی آدرس `https://<نام‌کاربری>.github.io/<نام‌ریپو>/` منتشر می‌شود.

### در اختیار گذاشتن برای دیگران

- **لینک اپ:** هر کس لینک را باز کند، اپ را با داده‌های خالیِ خودش دارد و می‌تواند آن را روی گوشی «نصب» کند.
- **قالب آماده:** از «تنظیمات ← فقط برنامه‌ی فعلی (JSON)» یک فایل بگیرید و بفرستید. گیرنده با «وارد کردن فایل» دقیقاً همان برنامه را تحویل می‌گیرد.

## تنظیم نمونه (فایل goal.xlsx)

نمونه‌ی داخل اپ از روی `goal.xlsx` ساخته شده و این ایرادها در آن اصلاح شده است:

| ایراد در فایل اصلی | اصلاح در اپ |
|---|---|
| جمع بودجه‌ی سناریوی توسعه‌ای **۲۸۹** است، ولی جدول الزامات و KPI نوشته بودند **۲۲۵** | هدف «سرمایه راه‌اندازی» و KPI هزینه به ۲۹۰ اصلاح شد. بودجه حالا از جمع هزینه‌ی فعالیت‌ها ساخته می‌شود (۲۸۹). |
| هزینه‌های نوشته‌شده داخل متن هدف‌ها با شیت بودجه نمی‌خواند (مثلاً نرم‌افزار ۳۶ در برابر ۲۲ تا ۲۷) | هزینه‌ها از متن حذف شد و به‌صورت عدد روی فعالیت‌ها ثبت شد. |
| ستون «هدف» در Action plan به جدول الزامات وصل نبود | هر فعالیت به الزام (هدف) خودش وصل شد. |
| ۱۱ الزام عملاً هیچ فعالیتی نداشتند (مثل عضویت حرفه‌ای، ذخیره احتیاطی، تجهیزات، مدیریت زمان، کد اقتصادی) | برایشان فعالیت اضافه شد. در یادداشت این فعالیت‌ها نوشته شده «افزوده‌شده در بازبینی نمونه». |
| پیشرفت کل فقط «انجام شد»ها را می‌شمرد و ستون درصد پیشرفت را نادیده می‌گرفت | پیشرفت حالا بر اساس درصد پیشرفت و وزن ساعت هر فعالیت حساب می‌شود. |
| موعدها داخل متن هدف بودند | موعد به یک فیلد تاریخ جدا منتقل شد. |

**تصمیم‌هایی که با خود شماست** (اپ این‌ها را در «سلامت برنامه» نشان می‌دهد):

- **ظرفیت:** جمع ساعت فعالیت‌ها حدود **۱۰۶۰ ساعت** است، در حالی که ظرفیت ۱۵ ساعت در هفته حدود ۷۸۰ ساعت در سال است. فاز ۱ به حدود **۳۵ ساعت در هفته** می‌رسد، یعنی بیش از دو برابر ظرفیت. باید کارها را کم کنید، عقب بیندازید یا واگذار کنید.
- **تاریخ‌ها:** ۱۲ فعالیت بعد از موعد هدفشان تمام می‌شوند. مثلاً منتور «از آبان» آمده ولی جلساتش از دی شروع می‌شود، و ثبت شرکت «تا آذر» آمده ولی فعالیتش تا اسفند طول می‌کشد. فقط شما می‌دانید کدام تاریخ درست است.
- **دو الزام تکراری:** «دانش قیمت‌گذاری» و «ساختار قیمت خدمات» عملاً یک هدف داشتند. در نمونه، اولی به «یادگیری مدل‌ها و ماشین‌حساب ROI» تغییر کرد.

## نقشه‌ی راه (برای ارتقای بعدی)

ترتیب پیشنهادی، از ساده به پیچیده:

1. **نسخه ۱.x:** گزارش PDF و چاپی، یادآور بازبینی هفتگی (اعلان PWA)، کشیدن و جابه‌جا کردن فعالیت‌ها روی نمای زمان‌بندی، و یک گالری قالب برای مشاغل مختلف (فایل‌های JSON در پوشه‌ی `src/data`).
2. **نسخه ۲:** ورود کاربر و همگام‌سازی ابری، مثلاً با Supabase، تا داده بین گوشی و کامپیوتر یکی شود. ساختار داده از الان نسخه‌دار است (`schemaVersion`)، پس فایل‌های قدیمی هم خوانده می‌شوند.
3. **نسخه ۳:** حالت تیمی و مشاوره‌ای (یک مشاور و چند برنامه‌ی مشتری)، تخصیص فعالیت به افراد، و ربات تلگرام برای یادآوری و ثبت سریع پیشرفت.

## ساختار پروژه

```
src/
  domain/      منطق اصلی بدون رابط کاربری: مدل داده، تاریخ شمسی، محاسبات، بررسی سلامت (+ تست)
  data/        نمونه‌ی آماده
  store/       ذخیره‌سازی محلی و «برگرداندن»
  io/          خروجی و ورودی JSON و Excel (+ تست)
  ai/          دستیار Claude (اختیاری)
  components/  اجزای رابط کاربری، نمودارها، ویرایشگرها
  pages/       صفحه‌ها
```

React 19، TypeScript، Vite، Tailwind CSS 4، Radix UI، Zustand، ExcelJS و فونت وزیرمتن.
